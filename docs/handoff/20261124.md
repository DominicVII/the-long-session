## Round 2: Academy papers (engine and data are Jupiter's; the reading UI is Neptune's)

The papers live in `G.academy = {v:1, n, lastDay, p:[paper...]}`. Only a seed and some numbers are stored per paper; the
text is rebuilt from them each time a paper is opened, and the rebuilt text is identical after a reload.

The stored record, roughly 150 bytes per paper:
```
{ no: 12,            // the paper's number; numbers are never reused
  d: 535,            // the day it was published
  b: "eo",           // the institution key; see onumAcademy.bodies
                     //   acad, rb, pi, eo, ss, ma, sa, id, uc, ec, hs
  s: 2893745123,     // the seed; every textual choice comes from it
  by: 3, sc: 1,      // the scholar index and the school index (the names come from the seed)
  tp: "m2" | ti: 1,  // the topic: an Academy discovery id (INQ_BY), or a domain topic index
  dm?: "econ",       // optional domain override
  k: [N, conf, eff, dissent, costK, years, guilder?, treasury?],   // the key numbers
  c: [9, 10, 11],    // citations: earlier papers in the same domain
  rb?: 7,            // the paper it replies to
  st: "held"|"failed", fb?: 15,   // its standing; if failed, the paper that overturned it
  rev?: 1,           // a discovery that changes society
  dec?: {o: 0|1|2, d: 540} }      // the cabinet's decision: 0 high, 1 moderate, 2 none
```

API, which reads only and never changes the save except through `decide` and `publish`:
- `onumAcademy.list()` returns `[{no, day, institution, field, title, school, scholar, cites, replyTo, status,
  overturnedBy, decided, revolutionary}]`.
- `onumAcademy.get(no)` returns a copy of the stored record.
- `onumAcademy.text(no)` returns the full paper as markdown-ish plain text:
  - `# Paper No. N: Title`, then an `Institution:` line;
  - then `## Abstract`, `## Research Question`, `## Background Literature` (cites "Paper No. N (day D, Institution)"),
    `## Methodology`, `## Findings`, `## Competing Interpretations`, `## Counterarguments`, `## Policy Recommendations`,
    `## Risk Assessment`, `## Forecast`, `## Public Response`, `## Cabinet Relevance`, `## Historical Significance`.
  - Citation links: in the text, match `/Paper No\. (\d+)/`.
- `onumAcademy.title(no)`, `.schools()`, `.scholars()` (ranked by citations and papers), `.prestige()` (institutions),
  `.failed()` (the archive of failed theories), `.decisions()` (open paper numbers), `.decide(no, 0|1|2)`, `.bodies`.
- `.open()` is Jupiter's plain stand-in reader, the phone app "Papers" (soc-acad). Neptune's paged view and library can
  replace it by overriding `pbAppGo("soc-acad")`.

Papers are published:
- for every Academy discovery (`inqDiscovered`);
- by one state body about every third day, on a deterministic schedule.

The archive keeps the newest 400 papers.

People (`window.onumPeople`):
- `story(id)` is a stable life story, the same text that "tell me about yourself" returns;
- `opinions(id)` are views held before you meet;
- `remembers(id, n)` returns real journal events by day;
- `recall(id)`, `reply(id, text)`, `gossip()` (people talking to each other; the log is `G.tkTalk.log`, at most 24 entries),
  `dissent(votes, v)`, `prompt(id)`.

## `ONUM.engine.ask(question) → entry`

One entry the Engine can stand behind. Built when asked, from numbers already in the save. Not stored as prose.

```
{
  question: string,     // the player's words, unchanged
  answer: string,       // plain language; never a field path such as (you.name)
  sourceKind: "statute" | "poll" | "engine-state" | "economy" | "inquiry" | "weather" | "none",
  sourceRef: string | null,  // stable id for you to key a citation, not to show raw: "statute/<id or day>", "approval", "engine/safety+p", "states/unrest", "inq/<id>", "weather/today"
  confidence: number,   // 0..1; 0 means it refused to guess
  wrongIf: string       // the condition under which this answer would be stale or unsound
}
```

Rules the accessor already enforces: it will not answer from a single shared word (so "cloud" is not "the weather is wind"); it will not answer a question that is only a config field name; every number in `answer` is the live simulation value (approval, aye/no, unrest, oversight, capability).

`ONUM.engine.hasSubstance(question)` is the same gate, if you need it before you render a prompt.

`onumAcademy.list/get/text/title/schools/scholars/prestige` are unchanged: `text(no)` builds the paper when opened from the stored numbers (`p.k`, day, school, citations). It does not write the prose back into the save.

## `G.histTier` (kept in the career save, compact)

```
{
  v: 1,
  vivid: 30,
  backed: number,          // day the IndexedDB pre-condense backup was first written
  records: [               // one compact record per condensed day
    {
      d: number,           // day
      k: "day" | "you" | "law",
      n: number,           // how many daylog notes that day
      talks: number,       // how many tlog remarks
      you: [{ t: string, k: string }],  // every act of the player's from that day, one line each
      laws: [{ title, aye, no, fate, id }],
      rose: string[],      // names, if the day's notes say someone rose
      fell: string[],
      t: string            // one-line summary (law and tally, who rose or fell, a scandal if any, numbers)
    }
  ],
  eras: [{ from, to, n, laws, you, t }],  // records older than 360 days roll in here; laws and the player's acts are also kept as stubs in records
  bios: {},                // reserved: later per-person numbers (beliefs, grudges, ambitions stay numeric)
  stats: { laws, vividFrom, condensedAt }
}
```

The last 30 days of `G.tlog` and `G.daylog` stay in full. `G.statute` is never deleted; a day-100 law remains citable on day 1000 through `citeLaw` and `ask`. The pre-condense backup (the vivid logs, statute, `mm`, and the Engine's lexicon as they were) lives only in IndexedDB, key `hist-backup`, so Dominic's data is not dropped.

Measured on a copy of the day-540 save (20.93 MB on disk; original files untouched): tracked logs went from 5,001,713 bytes to 1,593,733 (32% of what they were). The last 30 days stayed vivid (5,108 talks, 3,594 day notes). 66 earlier days became compact records. 500 of Dominic's older acts each still have a record. The Harvest Visa Act of day 105 is still on the roll. Opening Academy papers did not grow the stored academy (0%). Planted old conversations grew the log, then condense brought the size back to the same number (delta 0). The IndexedDB backup kept the full pre-condense tlog (16,253) and daylog (11,472), 9,493,559 bytes.
